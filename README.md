# Reconcile two extracts: Lattice Grid's audit mode

Drop last month's and this month's supplier-invoice extract — or use the
seeded pair the page ships with — and the grid's diff (audit mode) shows every
row that was added, removed or changed, the prior value on hover, running
totals, a status filter, a swap, and an export of just the exceptions.
Nothing you drop leaves the browser tab.

Live: https://toclocoinc.github.io/lattice-grid-demo-reconcile/

## What it shows

- **Two drop zones**, "Before" (last month) and "After" (this month), each
  taking a `.csv` or `.tsv` through `grid.import.preview`. The **after** file
  becomes the grid's own rows (`grid.import.apply(preview, { mode: 'replace' })`);
  the **before** file becomes the diff baseline (`grid.diff.setSnapshot(preview.records)`)
  and is never applied as live rows. The page ships with a seeded pair so it
  works with no upload.
- **Reconciliation table** — every row from `grid.diff`: a **Status** column
  (added/removed/changed/unchanged, drawn as a pill) you can filter with its
  own set filter; changed cells carry the prior value as `data-before`, shown
  on hover, via the grid's built-in diff painting — no extra wiring. Settled
  (removed) invoices sit pinned beneath the live rows, struck through
  (`diff.removedRows: 'pinned'`).
- **Summary tiles**, from `grid.diff.summary()`: added, removed, changed,
  unchanged, and the **net amount difference** — summed in JS over exactly the
  rows `grid.diff.statusOf` calls "changed", using `grid.diff.before()` for
  each one's prior amount. Built with `createStat`.
- **Swap** (`grid.diff.swap()`) — the page states which way round the
  comparison now runs.
- **Export exceptions** — a CSV of every added/changed/removed row, before and
  after columns included, through `grid.export.csv()`.
- A note that nothing you drop leaves the browser: both files are parsed and
  compared client-side; there is no server.

## The "status" column is a stamped field, not a computed column (F-RECON-1)

The natural way to add a status chip looked like a computed column reading
`grid.diff` in its `value.compute`. **That corrupts every row's diff status**:
`grid.diff`'s own column set includes every resolved column, computed ones
included, so a "status" column is itself compared against the snapshot on
every row. Its "before" read has no row to compute from (the diff engine asks
for a column's prior value with no current-row context), the compute throws,
and the resulting mismatch marks every row "changed" — regardless of whether
the underlying data actually differs. Reproduced with `node --test`-free
evidence: 5,000 rows, real recipe of 120 exceptions, computed-column status
reported 4,970 "changed" instead of 60. No per-column opt-out from diffing
exists (`docs/api/grid.html` §`grid.diff`, `packages/core/src/model/diff.js`).

The demo works around it by **not using a computed column for anything that
reads `grid.diff`**. `sync()` in `app.js` re-stamps `status`,
`supplierBefore`, `amountBefore` and `vatRateBefore` as plain **stored
fields** on every live row (from `grid.diff.statusOf`/`before()`) and reloads
— fields the snapshot never carries are read as an unrelated "added-column",
which cannot pollute a row's own status. `sync()` runs after loading either
side and after every swap (the live rows are stripped of the stamped fields
immediately before `grid.diff.swap()`, or they ride into the new snapshot and
reappear as a spurious mismatch once the sides trade places).

This is a real grid gap, not a demo-specific one: any column whose value
depends on `grid.diff` is unsafe today. Filed as **F-RECON-1** for the grid
team; not worked around inside the grid itself.

## Data

`data/invoices-before.csv` and `data/invoices-after.csv` — 5,000 synthetic
supplier invoices each, generated by `tools/gen-data.mjs` (deterministic,
seeded; re-running it reproduces the files byte-for-byte). Nothing here is a
real supplier or invoice. The two files differ in exactly 120 rows, by a
disjoint recipe:

| Category | Rows | What changed |
|---|---:|---|
| Removed (settled) | 30 | Present in "before", absent from "after" |
| Amount changed | 40 | A correction or credit note |
| VAT rate changed | 15 | 20% &rarr; 21%, a rate rise on invoices raised after a cut-over date |
| Supplier renamed | 5 | One supplier, "Meridian Supplies Ltd" &rarr; "Meridian Supplies Limited" |
| Added | 30 | New invoices, not in "before" |

`tools/verify-diff.mjs` is the independent ground truth: a plain CSV parse
with no grid involved, used to check the grid's own KPI tiles agree with it
(they do — see the headless check below).

## Run it locally

The page loads Lattice Grid 1.77.0 from the jsDelivr CDN. To try a local build
instead, copy the grid's package (`dist/`) to `vendor/` (not part of this
repository) and open the page with `?local`. Serve the folder with any static
server, for example:

```
python3 -m http.server 8711
```

and open http://localhost:8711/. No licence key is needed on localhost.
Add `?theme=dark` to see the page under `data-theme="dark"`.

## Grid features used

`grid.diff` (`setSnapshot`, `summary`, `statusOf`, `before`, `swap`,
`swapped`, `removedRows: 'pinned'`), `grid.import` (`preview`, `apply`),
`grid.export.csv` (`rows: 'selected'`, `hidden`, `processCell`),
`grid.selection`, `grid.filters`, `createStat`, `filterRow`, the `set` column
filter, the `pill` cell decoration with a value-to-token `variant` map, and
`modules/layout` for the four-window page.
